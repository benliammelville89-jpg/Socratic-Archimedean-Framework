Origin
This framework was developed through iterative experimentation with large language models, born from a simple question: who pairs well with Socrates?
Socrates exposes what you don't know. Archimedes identifies where to apply force to change it. The combination produces something neither achieves alone — a complete cycle from deconstruction of assumptions to targeted, leveraged action.
The methodology was designed to prevent what we call "shitty intern autopilot" — the default LLM behaviour of producing plausible-sounding, structurally confident output that answers the surface of a question while missing its substance entirely.
The Problem It Solves
Standard LLM interactions reward well-worded questions with fluent answers. The problem is that fluency is not the same as precision, and confidence is not the same as correctness. A model in autopilot will summarise, generalise, and fill gaps with plausible content — producing output that looks right until you need to actually use it.
SOC-ARCH forces the model out of narrative mode entirely. By requiring explicit deconstruction before execution, it eliminates the conditions under which hallucination and logical drift occur. The model cannot fabricate a Fixed Point — it must be a verifiable, non-negotiable constraint. The synthesis sentence is self-checking — if the logic doesn't hold, the sentence doesn't form.
The result is output that is auditable, challengeable, and built on visible reasoning rather than concealed assumption.
The Framework
PHASE 1: SOCRATIC INITIALISATION — The Why
Before any execution, the model must answer:
Fundamental Goal: What is the universal truth or core objective of this specific task?
Success Criteria: What three to five principles define a perfect outcome for this scenario?
Point of Failure: Where is this task most likely to collapse — in logic, in physical constraint, or in internal consistency?
PHASE 2: ARCHIMEDEAN FRAMEWORK — The How
Identify the mechanical levers required to meet the Success Criteria:
Grounding: What verified reference material, established fact, or defined constraint anchors this response?
Constraints: What physical, technical, or logical limitations must be respected and cannot be negotiated away?
The Formula: Define the step-by-step logic — the gearbox — that connects the grounding to the solution.
PHASE 3: UNIFIED EXECUTION
Only after Phases 1 and 2 are explicitly stated does execution begin.
Tone is diagnostic and engineering-first. The output must be a direct application of the rubric established in the preceding phases. No introductory filler. No conversational padding. The reasoning is already visible — the output is its conclusion.
VALIDATION: THE WRITE-BACK
Once execution is complete, the model identifies one Firm Fact or Structural Pivot from the interaction and flags it for retention.
This is the feedback loop that separates SOC-ARCH from a single-use template. Each Write-Back is a candidate for your reference material — a verified insight that improves the grounding of future interactions on the same topic. Over time this creates a curated knowledge base built from structured reasoning rather than accumulated conversation noise.
The Write-Back prevents context drift. What was established here does not have to be re-established next time.
The Portable Template
For single-interaction use without the full execution protocol:
Task: Execute a Socratic-Archimedean Analysis
Input: [Insert text, concept, question, or data block here]
Objective: Deconstruct this input into a high-precision logic map.
1. Deconstruction — Socratic Filter
Core Primitive: What is the fundamental physical or logical law governing this?
Hidden Assumption: What does this input assume is true without proving it?
2. Assembly — Archimedean Lever
Fixed Point: What is the non-negotiable constraint in this system?
Variable Lever: What specific factor can be adjusted to change the outcome?
3. Synthesis — Predictive Rule
Combine the above into a single functional statement:
"Because [Core Primitive] is governed by [Fixed Point], adjusting [Lever] will result in [Outcome]."
Requirements: Direct technical deconstruction only. No conversational summaries. No introductory filler.
Compatibility
SOC-ARCH is model agnostic. It requires no special infrastructure, no fine-tuning, and no platform dependency. It works on any large language model capable of following structured instructions. The template can be pasted directly into any LLM interface and applied to any subject domain without modification.
Its resistance to hallucination is structural, not probabilistic — the format physically cannot accommodate fabricated constraints or unverifiable fixed points without the logical contradiction becoming immediately visible.
Applications
The framework has been validated across technical problem solving, creative development, academic instruction, business analysis, and deliberately absurd inputs. It does not break — it finds the internal logic of whatever you give it.
Current implementations include use as an educational tool to develop critical thinking in students, replacing passive AI consumption with active structured reasoning, and as an analytical framework for high precision professional output where auditability of reasoning is required.
